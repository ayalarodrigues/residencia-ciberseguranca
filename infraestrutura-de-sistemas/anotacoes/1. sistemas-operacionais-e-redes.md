## Sistemas Operacionais e Redes de Computadores - 12/03

## 1. O que é um Sistema Operacional

O **Sistema Operacional (S.O.)** é o software responsável por gerenciar os recursos de hardware e oferecer uma interface entre o usuário, as aplicações e a máquina.

Do ponto de vista do usuário, o S.O. pode ser entendido como a interface que permite utilizar o computador de forma prática. Já do ponto de vista técnico, ele é o software que controla o uso de recursos como:

- processador
- memória
- disco
- dispositivos de entrada e saída

Em um sistema computacional, várias aplicações e usuários podem utilizar os mesmos recursos ao mesmo tempo. Por isso, é necessário existir um mecanismo central de controle. Esse papel é exercido pelo sistema operacional. :contentReference[oaicite:1]{index=1}

### Evolução dos Sistemas Operacionais

Os sistemas operacionais evoluíram de acordo com as necessidades dos usuários e do hardware disponível em cada época.

Os primeiros sistemas operacionais não precisavam de tanta usabilidade nem de respostas tão rápidas. Além disso, muitos deles eram escritos em **Assembly**, o que tornava sua programação e manutenção mais difíceis. Posteriormente, com o uso da linguagem **C**, os sistemas passaram a ser mais modulares, portáveis e adequados a diferentes arquiteturas. :contentReference[oaicite:2]{index=2}

### Características importantes

Dois pontos-chave no estudo de sistemas operacionais são:

- **multiusuário**
- **multitarefa**

Essas características são importantes porque exigem do sistema operacional uma boa gerência de recursos. O objetivo é garantir a **multiprogramação**, isto é, permitir a alternância rápida entre processos, dando a impressão de que várias tarefas estão sendo executadas em paralelo. 

### Exemplos de Sistemas Operacionais para PCs

- Windows
- macOS
- Linux
- Chrome OS

## 2. Estrutura Geral do Sistema Computacional

Em uma visão simplificada, temos:

- o **usuário**
- as **aplicações**
- o **sistema operacional**
- o **hardware**

As aplicações executam sobre o sistema operacional, e o sistema operacional gerencia os recursos de hardware. Assim, sempre que uma aplicação precisa realizar alguma operação mais sensível — como acessar a memória, o disco ou um dispositivo — ela faz uma solicitação ao sistema operacional. :contentReference[oaicite:4]{index=4}

### Principais componentes de hardware

- placa-mãe
- disco
- memória
- processador
- placa de vídeo

Os componentes mais destacados nessa aula foram:

- **memória**, pois os programas são carregados nela em forma de processos
- **CPU**, responsável pela execução das instruções

### Outros componentes importantes

- **Registradores**: memórias extremamente rápidas incorporadas ao processador
- **Cache**: memórias integradas ao processador, usadas para acelerar acessos frequentes
- **Armazenamento secundário**: disco rígido ou SSD, usado para armazenamento persistente
- **Dispositivos de entrada e saída**: teclado, mouse, monitor, impressora, disco etc. :contentReference[oaicite:5]{index=5}

## 3. Estrutura de um Sistema Operacional

Um sistema operacional é composto por vários módulos, cada um responsável por uma parte do gerenciamento do sistema.

### Kernel

O **kernel** é o núcleo do sistema operacional, frequentemente chamado de “cérebro” do sistema. Ele é responsável pelo gerenciamento dos recursos principais.

### Drivers

Os **drivers** são módulos responsáveis pela comunicação entre o sistema operacional e os dispositivos de hardware.

### Código de inicialização

É o código responsável por iniciar o sistema operacional quando a máquina é ligada.

### Programas utilitários

São programas que facilitam o uso do sistema operacional e oferecem funções adicionais ao usuário. :contentReference[oaicite:6]{index=6}

---

## 4. Chamadas de Sistema

As **chamadas de sistema** são mecanismos que permitem que programas solicitem serviços ao sistema operacional.

Os processadores normalmente trabalham com dois modos de operação:

### Modo usuário

Nesse modo, os programas têm acesso limitado ao hardware e a instruções privilegiadas. Eles não podem interagir diretamente com os recursos mais críticos do sistema.

### Modo kernel

Nesse modo, o sistema operacional possui acesso ao conjunto total de instruções do processador e pode controlar diretamente os recursos de hardware. :contentReference[oaicite:7]{index=7}

---

## 5. Processos

Um **processo** pode ser entendido como um **programa em execução**.

Essa distinção é importante:

- **programa**: entidade passiva
- **processo**: entidade ativa

Todo processo precisa de recursos para executar suas tarefas, como:

- memória
- processador
- entrada e saída

Além disso, o próprio sistema operacional também é composto por vários processos. Em muitos sistemas, o processo é a principal unidade de trabalho. :contentReference[oaicite:8]{index=8}

### Problema de executar apenas um programa por vez

Se apenas um programa fosse executado por vez, poderiam surgir gargalos. Em vários momentos, alguns recursos ficariam ociosos.

Exemplo:
se um programa estiver esperando uma operação de escrita em disco, a CPU poderia ficar sem uso. Daí vem a importância da multiprogramação. :contentReference[oaicite:9]{index=9}

---

## 6. Estrutura de um Processo

Um processo possui, entre outros, os seguintes segmentos de memória:

### Pilha (Stack)

Área que armazena:

- parâmetros de função
- endereços de retorno
- variáveis locais

### Heap

Área usada para **alocação dinâmica de memória**.

### Dados

Armazena dados usados pelo programa, como variáveis globais.

### Texto

Contém o código executável do programa. :contentReference[oaicite:10]{index=10}

---

## 7. Estados do Processo

Um processo passa por diferentes estados ao longo da sua vida.

### Novo

Estado inicial, logo após o processo ser criado.

### Pronto

O processo já está apto a executar, mas ainda aguarda disponibilidade da CPU.

### Em execução

O processo está efetivamente utilizando a CPU.

### Em espera

O processo aguarda algum evento, geralmente relacionado a dispositivo de entrada e saída.

### Concluído / encerrado

O processo terminou sua execução.

### Observação importante

Um processo em execução pode ser interrompido e voltar ao estado de pronto caso chegue outro processo com prioridade maior. Isso caracteriza **preempção**. :contentReference[oaicite:11]{index=11}

---

## 8. PCB — Bloco de Controle de Processo

Cada processo é representado internamente pelo sistema operacional por um **PCB (Process Control Block)**.

Esse bloco é fundamental porque armazena todas as informações necessárias para controlar e retomar a execução do processo.

O PCB normalmente contém:

- estado do processo
- número do processo
- contador de programa
- registradores
- limites de memória
- lista de arquivos abertos

Essas informações são importantes porque, quando ocorre uma troca de contexto, o sistema precisa salvar o estado atual do processo para retomá-lo depois do ponto correto. :contentReference[oaicite:12]{index=12}

---

## 9. Escalonamento de Processos

O escalonamento é o mecanismo usado pelo sistema operacional para decidir:

- qual processo será executado
- quando ele vai usar a CPU
- quando ele será suspenso
- quando voltará a executar

### Objetivos importantes

#### Multiprogramação

O objetivo da multiprogramação é garantir que sempre exista algum processo em execução, maximizando a utilização da CPU.

#### Compartilhamento de tempo

O objetivo do compartilhamento de tempo é alternar rapidamente a CPU entre os processos, dando aos usuários a sensação de que vários programas estão sendo executados em paralelo. 

---

## 10. Filas de Escalonamento

### Fila de jobs

Quando um processo entra no sistema, ele pode ser colocado inicialmente em uma **fila de jobs**, contendo processos recém-admitidos.

### Fila de prontos

Contém os processos que estão na memória principal e aguardam execução na CPU.

### Filas de dispositivos

Se um processo solicita I/O para um dispositivo compartilhado, ele pode ir para a fila daquele dispositivo enquanto aguarda atendimento. :contentReference[oaicite:14]{index=14}

---

## 11. Mudança de Contexto

Quando o sistema remove um processo da CPU e coloca outro, ocorre uma **mudança de contexto**.

Nesse momento:

1. o estado do processo atual é salvo no PCB
2. o estado do novo processo é carregado
3. a CPU passa a executar o novo processo

Isso gera **overhead**, porque esse tempo não é usado para executar trabalho útil do processo.

### Thrashing (observação da aula)

Nas anotações aparece “trash”, mas o termo técnico correto é **thrashing** em outro contexto de memória; aqui a ideia apresentada foi de um cenário ruim em que há mudanças excessivas de contexto, desperdiçando muito tempo do sistema. Como conceito da aula, o mais importante é lembrar que **troca de contexto em excesso prejudica o desempenho**. :contentReference[oaicite:15]{index=15}

---

## 12. Escalonadores

Um processo passa por várias filas ao longo de sua vida. Para isso, o sistema operacional usa diferentes escalonadores.

### Escalonador de longo prazo

Seleciona processos do disco e os leva para a memória / fila de prontos.

### Escalonador de curto prazo

Escolhe, com alta frequência, qual processo da fila de prontos vai para a CPU.

### Escalonador de médio prazo

Pode remover temporariamente processos da memória e devolvê-los ao disco para reduzir o grau de multiprogramação.

Esse processo recebe o nome de **swapping**. :contentReference[oaicite:16]{index=16}

---

## 13. Processos limitados por CPU e por I/O

Os processos podem ter perfis diferentes:

- **CPU-bound**: usam mais a CPU
- **I/O-bound**: fazem mais operações de entrada e saída

É importante que o escalonador de longo prazo escolha um **bom mix de processos**, pois se o sistema colocar apenas processos CPU-bound na fila de prontos, pode superutilizar a CPU e deixar os dispositivos ociosos. Já uma boa mistura entre CPU-bound e I/O-bound melhora o aproveitamento geral do sistema. :contentReference[oaicite:17]{index=17}

---

## 14. Concorrência x Paralelismo

### Concorrência

É a ilusão de que vários processos estão sendo executados ao mesmo tempo devido à rápida alternância entre eles.

### Paralelismo

É quando vários processos realmente executam ao mesmo tempo em núcleos diferentes. :contentReference[oaicite:18]{index=18}

---

## 15. Critérios de Escalonamento

Alguns critérios usados para avaliar algoritmos de escalonamento:

- **Utilização da CPU**
- **Throughput**: número de processos concluídos por unidade de tempo
- **Tempo de espera**
- **Tempo de resposta** :contentReference[oaicite:19]{index=19}

## 16. Algoritmos de Escalonamento

### FCFS — First Come, First Served

O primeiro processo a chegar é o primeiro a ser atendido.

A fila usada é do tipo **FIFO**.

#### Exemplo da aula

Se os processos chegarem todos no tempo 0:

- P1 = 24 ms
- P2 = 3 ms
- P3 = 3 ms

Tempo médio de espera:

- P1 espera 0
- P2 espera 24
- P3 espera 27

\[
(0 + 24 + 27)/3 = 17 \text{ ms}
\]

O FCFS pode gerar tempo médio de espera alto se processos longos forem executados primeiro. :contentReference[oaicite:20]{index=20}

---

### SJF — Shortest Job First

O algoritmo SJF associa a cada processo a duração do próximo pico de CPU.

Quando a CPU está disponível, escolhe-se o processo com o menor tempo de execução estimado.

#### Exemplo da aula

Se todos chegam ao mesmo tempo:

- P4 = 3
- P1 = 6
- P3 = 7
- P2 = 8

A ordem será:

P4 → P1 → P3 → P2

O tempo médio de espera fica menor que no FCFS. 

#### Observação importante

Na prática, o problema do SJF é que normalmente **não sabemos de antemão** quanto tempo um processo levará para executar.

#### SJF com preempção

Quando um processo com menor tempo restante chega, ele pode interromper o processo atual. Isso torna o algoritmo mais eficiente em alguns cenários, mas também aumenta o custo de troca de contexto. :contentReference[oaicite:22]{index=22}

---

### Round Robin (RR)

O Round Robin é semelhante ao FCFS, mas adiciona **preempção**.

Define-se uma pequena unidade de tempo chamada **quantum**.

Cada processo pode usar a CPU por, no máximo, esse tempo.

Se não terminar, ele volta para o fim da fila de prontos.

#### Características

- usa fila FIFO
- novos processos entram no final da fila
- o sistema busca fazer com que todos os processos avancem juntos

#### Observação importante

Se o quantum for muito pequeno, o overhead de troca de contexto aumenta muito. Se for muito grande, o algoritmo se aproxima do FCFS. :contentReference[oaicite:23]{index=23}
